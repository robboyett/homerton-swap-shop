# Runbook

**Parent:** [AGENTS.md](../AGENTS.md)

When something looks broken, read this first. When you add a way something can fail, add a row. Symptom, cause, what to do. Newest at the top. No severity levels.

| Symptom | Cause | What to do |
|---------|-------|------------|
| Someone sees "something went wrong at our end" | A server error the page did not expect: the database not answering, a route throwing, Open Library down in a path that does not catch it. The page shows nothing technical on purpose | The detail is in the Vercel function logs for that minute (`vercel logs`, or the dashboard). Fix the cause; if it is a new way to fail, add its row here |
| The pile on "add books" came back after a reload, or will not go away | The pile is kept in that browser's storage until it is published or every book is taken out, because phones reload background tabs without asking | Publish it, or take the books out one by one. It is per browser, so a different phone starts empty |
| A book is "off the shelf" on `/admin` with the reason `taken down by the owner`, and the owner wants it back | Owners can take their own book down but not put it back (ADR 0018) | "put it back on the shelf" on `/admin`, or they add it again |
| A book someone else just reserved or removed is still showing | Pages ask again every thirty seconds while visible, and when the tab comes back (ADR 0016). Nothing is pushed | Wait half a minute, or switch away and back. If it never updates, the tab is in the background or the fetch is failing: open the network tab |
| Adding a photo answers `that photo is too big` or `that is not a photo` | The server takes images up to 3 MB; the phone shrinks a photo to 1200px JPEG before sending, so this means the shrink did not run (an old browser) or the file was not an image | Try a different photo, or a different browser. The plain cover stays meanwhile |
| Adding a photo answers `this book already has a cover` | Someone else filled the gap seconds earlier, or the book got an Open Library cover (ADR 0015) | Nothing to do; reload to see it. The upload that lost was deleted from the store |
| Every photo upload fails with a server error, and the log says the blob token is missing | `BLOB_READ_WRITE_TOKEN` is not in the environment. The store is linked to the Vercel project, which sets it; locally it comes with `vercel env pull .env.local` | Pull the env again. If the store was unlinked, relink it from the Vercel dashboard or `vercel blob` |
| Every page sends someone to `/welcome`, and they say they have done it | They have not given a number yet: the welcome page shows until `whatsapp_number` is set (ADR 0014). The admin list marks them "not signed in yet" | Ask them to finish the page. If the box refuses their number, it wants +44 then ten digits. Rob can correct it later on `/admin` under "edit", once they have given one |
| "I'd like this" or publishing answers `add your mobile number first` | The person has no number on file, so there is nothing to show the other side (ADR 0014). Should not happen through the site, which routes them to `/welcome` first; it can through a stale tab | Reload; the welcome page appears. Rob can see who it is on `/admin` |
| A book is gone from "requests" between one look and the next | Only reserved books are listed (ADR 0013). It was collected, put back on the shelf by the other side, or taken off by an admin | Nothing to do. The shelf shows whether it is back; the book page shows its state |
| A book someone reserved has vanished from their page and the shelf, with no message | An admin took it off the shelf (ADR 0012), or its owner did (ADR 0018); removal ends any reservation and the page is a 404 for everyone | Nothing is wrong. The book is on `/admin` under "off the shelf" with "put it back", and the reason if one was given |
| Someone says their password stopped working, and sign-in says the usual "don't match" | They may have been removed (ADR 0012): a removed account is treated as nobody by sign-in, on purpose, with no different message | Look for them on `/admin`; "let them back in" restores sign-in. Their books stay removed until restored one by one |
| Removing an account seemed to half work: they are out, but a book of theirs is still on the shelf | Removal is three statements, not a transaction (ADR 0012, point 5); a request died between them | Press "remove" again. Every step is safe to repeat |
| `/admin` is a 404 for someone who should see it, or `admins only` from the API | Only a profile with `is_admin` true gets the screen, and that is Rob alone at first. The flag is read from the database on every call, never from the cookie | If a second admin is wanted, that is a decision for `docs/plan.md`; until then, one UPDATE on `profiles.is_admin` by hand |
| Making an account says `that email already has an account` | Emails are the username and unique, matched trimmed and lower-cased | Find them in the list on `/admin`; if they have forgotten their password, "new password" is next to their name |
| On "add books" there is no camera frame, only the number box | The browser refused the camera: permission was declined, the page is not on HTTPS (Vercel always is; a LAN address in dev is not), or the device has no camera | Allow the camera for the site in the browser's settings and reload. Typing the number always works meanwhile |
| The camera frame says `starting the camera` and never changes | The browser is still asking for permission, or the decoder is still downloading its WebAssembly (about a megabyte, once). If the decoder fails to load, the frame goes away and the number box takes over, so a frame that stays is a frame still waiting | Answer the permission prompt; give it a few seconds on a slow connection. If it is still there after that, reload once, then type the number |
| The camera is on but a barcode is never read | Too dark, too close, or the barcode is the shop's price sticker rather than the publisher's (only 978/979 codes are books) | More light, hold it further back, find the barcode that starts 978. Or type the number |
| Looking a book up says `the library isn't answering` | Open Library is slow or down; each request has an eight-second limit and we send three per book | Wait a minute and try again, or type the title and author in. Nothing is lost: the pile stays in this browser until you publish or take the books out |
| Looking a book up says `the library hasn't heard of that one` | Open Library has no record for that ISBN, which is common for older British children's books and activity books | Type the title and author; it goes in the pile with a plain cover. If the number was mistyped, try again |
| A looked-up book lands in the wrong section or age band | The section and ages are a guess from Open Library's subjects and page count (`guessShelf` in `server/services/openlibrary.ts`) | Tap the right one in the pile before publishing. If the same kind of book is guessed wrong twice, adjust the guess |
| "I'd like this" answers `someone else got there first`, or a move says `nothing to undo` | Two people pressed within moments of each other, or the page was stale. The database decided (docs/data.md, rule 1) and the page redrew itself from the answer | Nothing. This is the product working. If it happens with nobody else around, look at the item row: its status is the truth |
| `vercel env add NAME preview --value … --yes` answers `action_required: git_branch_required` and tells you to run the command you just ran | The globally installed Vercel CLI is old (54.x). The current CLI accepts the flag form | `npx -y vercel@latest env add NAME preview --value … --yes`, or upgrade the global CLI. Production and development were never affected |
| Every page errors with `NUXT_SESSION_SECRET is not set, or is shorter than 32 characters` | The sealed session cookie needs a key (ADR 0009). It is set in the Vercel project for all three environments; locally it has to be in `.env.local` | `vercel env pull .env.local`. To rotate it, set a new 64-hex value in Vercel and redeploy; everyone is signed out, which is the whole effect |
| Sign-in says `that email and password don't match` for someone who swears it does | Email is matched trimmed and lower-cased, so it is almost always the password. There is no reset flow on purpose (ADR 0009) | Rob opens `/admin`, taps "new password" next to their name, and sends them what it shows, privately. It is shown once |
| `POST /api/first-admin` answers 409 `there is already an account` | The route works only while `profiles` is empty. It made Rob's account once and is finished | Nothing. Every later account comes from the admin screen. If it fires on a database you believe is empty, it is not: check before deleting anything |
| `pnpm db:generate` fails with `Cannot find module '~~/shared/schema'` | drizzle-kit reads `server/services/db/schema.ts` outside Nuxt, so Nuxt aliases mean nothing to it | Import shared code into the Drizzle schema by relative path (`../../../shared/schema`), never by alias |
| `nuxt typecheck` is green but a type error is sitting in `server/` or `shared/` | The root `tsconfig.json` is extending one of the generated per-project configs instead of referencing all four. `.nuxt/tsconfig.json` is the app project and excludes `server/`, so a server file is never checked | Keep the root `tsconfig.json` as `files: []` plus references to `.nuxt/tsconfig.{app,server,shared,node}.json`. `nuxt typecheck` then runs in build mode over all four. To confirm, run `pnpm exec vue-tsc --noEmit -p .nuxt/tsconfig.server.json` directly |
| Every request that touches data fails with `DATABASE_URL is not set` | No connection string locally. Neon is provisioned through the Vercel Marketplace, so the value lives in the Vercel project rather than in anyone's head | `vercel env pull .env.local` in the repo root. That is the one file `pnpm dev` and `pnpm db:migrate` read (`nuxt dev` alone would read `.env`, so the script passes `--dotenv .env.local`). Gitignored. `.env.example` names every key with no values |
| A query fails with `relation "items" does not exist`, or `column ... does not exist` right after a merge | A migration in `drizzle/` has not been applied to the database that deployment uses. This is the exact failure ADR 0002 exists to prevent, so treat it as a process miss, not a one-off | `pnpm db:migrate` against that database, then redeploy. Apply the migration *before* merging the code that needs it, which is the order ADR 0002 names. Never `drizzle-kit push` at a database anything depends on |
| A phone screenshot looks like the layout overflows to the right | Headless Chrome clamps its window to about 500px wide, so `--window-size=390,844` lays the page out at 500 and then crops the image to 390. Nothing is wrong with the page | Shoot phone widths at `--window-size=500,900`. That is still below the 700px breakpoint, so it exercises the phone layout; it just is not 390. For a true 390 use Chrome's device toolbar by hand. Measured 8 Oct: `.page=500`, `window.innerWidth=500` at a requested 390 |
| `pnpm check` fails with `BLOCKED: no-real-numbers: <file>:<line>` | A UK mobile number outside the Ofcom drama range is in the tree. The repo is public, so a number committed once is public forever | Replace it with one from `07700 900000`–`07700 900999`. If it is a real neighbour's number, it belongs in the database, entered by them, and never in a file. |
| `pnpm check` fails with `BLOCKED: deps-allowed: <name> is phase n, docs/phase.md says m` | A dependency on the allow-list belongs to a later phase | Wait for that phase. If we mean to move now, write an ADR and bump `docs/phase.md` in the same PR. |
| `pnpm check` fails with `BLOCKED: deps-allowed: <name> is not in docs/allowed-deps.txt` | A dependency was added that isn't on the list | If it belongs to this phase, add the line with its phase and why. If not, remove it or write an ADR. |
| `pnpm check` fails with `BLOCKED: deps-allowed: <name> is on the denied list` | A dependency we've already decided against | Read the reason on the line. The answer is plain CSS, a small function, or a conversation with Rob. |
| `pnpm check` fails with `BLOCKED: seams: <file> imports <package>` | A page or API route imports a vendor package directly | Move the call into `server/services/` and import the service instead. |
| Commit refused with lint or type errors | lefthook ran `pnpm check` | Run `pnpm check` yourself, read the first error, fix the code, not the check. |
| Stop hook keeps firing and the agent can't ask a question | The hook isn't guarded on `stop_hook_active` | Fix `.claude/hooks/stop-check.sh`; it should run once per "done", not on every stop. |
| Files like `package 2.json` appear in the repo | Finder, iCloud or Dropbox made conflict copies | Delete them. `.gitignore` refuses `* 2` and `* 2.*`. Keep the clone out of any synced folder; this one lives in `GitHub.nosync` for that reason. |
